# HR / 面试官三分钟演示

## 0:00–0:30 说明问题

“这是我根据多模态取证思路实现的视频质检 demo。项目重点是把模型判断组织成有证据、有边界、可复核的工程流程。目前合成素材可离线运行，真实视频语义检查提供了可配置模型接口。”

## 0:30–1:30 跑出一个可解释结果

在首页点击「示例视频」，默认打开潜水视频与预填提示词。若要做可重复的离线演示，在「当前视频 / 切换样例」中选择「雨夜档案 · 外观漂移」，选择离线样例演示并开始质检。视频经过真实解码，镜头圈选器生成带帧号和时间戳的 4×2 网格，探针逐镜头记录外套像素测量。报告中的 Shot #4 发生变化，点击跳转后与前镜头对照。说明离线检测基于已知色块几何，不能用于任意真实人物。

## 1:30–2:10 展示工程结构

展开「检测过程与技术详情」，在「证据与记忆」中切换实体档案，展示外观取值冲突；打开证据台账，展示行动目的、区间和工具结果。解释完整台账用于追溯，有限摘要用于控制上下文，高分辨率原始数据归档后清空。

## 2:10–2:40 展示成本与边界

切换黑帧样例并运行：便宜规则命中后提前终止，没有模型调用。再提及正常样例虽然外套测量一致，仍因语义维度未覆盖而显示“需人工复核”，系统不会把未检查写成通过。

## 2:40–3:00 展示闭环

导出 JSON，保存一条人工复核意见。说明复核记录与评测数据分开存储；真实模型输出需要镜头校验、二次采样复核和步数限制。打开测试结果说明可重复验证的范围。

## 面试时可以说的实现成果

“实现了本地视频质检工作台，包含真实解码和规则预检、自适应镜头采样、结构化三层记忆、预算约束、报告导出和人工复核。通过合成视频回归测试验证了工具链，并提供兼容视觉 API 的真实模型适配层。”

不要把原材料中的 600 条内部数据、84.3% 准确率、线上流量或成本下降写为本项目成果。没有真实 Key 联调、自然视频标注评测和线上数据时，应直接说明尚未验证。简历可以写“个人 demo / 工程实现”，并根据你实际理解和后续完成的工作调整表述。

## 建议准备的回答

| 问题 | 回答重点 |
|---|---|
| 为什么不一次看完整条视频？ | 证据定位与跨镜头属性追踪；但是否优于直答需要同数据同模型对比实验 |
| 怎么防止上下文膨胀？ | 只读最新焦点、结构化实体与近期摘要，完整台账落盘 |
| 离线和真实模式区别？ | 确定性色块测量与模型视觉判断明确分开；不隐藏模拟部分 |
| 为什么正常样例还需要复核？ | 目前没有完成语义和音画检查，不能宣称全面通过 |
| 什么是集合 F1？ | 预测镜头集合与金标集合的精确率/召回率调和平均 |
| 目前主要不足？ | 没有 ASR、生产标定、自然视频评测、自动镜头切分和并发部署 |

## 本地 Ollama 演示补充

配置本机模型后，运行方式会显示模型完整名称。可以先跑 `scripts/ollama_smoke.py` 检查两帧视觉输入，再从工作台运行完整取证。报告中应看到 `provider=ollama` 与非零的实际模型 Token。本地 Token 表示计算用量，不是云端账单。

如果被问到模型选型，可说明：当前机器是 V100 16GB，默认使用 Qwen3-VL 8B 的指令版。默认 `8b` 标签的思考行为会使短输出预算耗尽，因此使用明确的 `8b-instruct` 标签，并通过真实调用验证 JSON。运行失败会显示错误，不用离线报告假装模型成功。

完整模型运行的结果可能与离线合成检测不同。演示中应区分“模型连通、工具链完成”和“判断正确”；自然视频准确率需要另外建设金标集进行验证。
